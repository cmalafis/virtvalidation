VM migration validation platform · open source

Prove the migration
actually worked.

VirtValidate records what your VMs looked like on VMware, plans the migration into dependency-ordered waves with MTV-ready YAML, then checks that each VM still looks right on OpenShift Virtualization. It runs fully air-gapped with local inference — or against a governed model endpoint inside your own perimeter when you have one. Built for federal, defense and regulated environments.

System architecture

How it all fits together

One appliance, reached over SSH in both directions. It never authenticates to your OpenShift cluster — you declare what the target looks like and VirtValidate emits manifests against that description.

Source — VMware
vSphere VMs
Reached over SSH with a per-wave key. Read-only commands only.
Baseline collector
Scheduled capture over a 3–7 day window, so normal variation is distinguishable from migration damage.
RVTools / CSV inventory
Multi-vCenter exports routed per row to the right registered source.
→
VirtValidate appliance
Web console
PatternFly 6. Overview · Configure · Discover · Migrate · Verify · Administration.
FastAPI backend
Inventory, SSH collection, deterministic diff engine, plan pipeline, MTV emitter, reports.
PostgreSQL
VMs, baselines, plans, runs, and three append-only audit streams.
Pluggable inference
Ollama, KServe, MaaS or TrustyAI Guardrails — selected at runtime from the Settings page.
→
Target — OpenShift Virt
Declared target catalogs
Clusters, namespaces, NADs and StorageClasses you describe. No cluster credentials are stored.
MTV / Forklift YAML
Per-wave Plan, NetworkMap and StorageMap. You apply it; VirtValidate does not migrate.
Post-migration validation
Six-dimension diff against the baseline, with a per-VM verdict and an exportable report.
End-to-end workflow

The migration validation lifecycle

The console's navigation is ordered to match this sequence, and the Overview page tracks which setup steps are done.

01
Configure
Register vCenter sources and OpenShift targets, describe the target's networks, storage classes and namespaces, then map vSphere resources onto them and run preflight.
02
Discover
Import inventory from RVTools or CSV, label environments, and optionally run a network or storage design review against your proposed OCP design.
03
Baseline & plan
Capture baselines over several days, then generate a plan: deterministic partitioning and wave packing, with the LLM writing per-wave rationale. Export the MTV YAML.
04
Run & verify
Dry-run a wave to see the exact commands, capture its baseline, migrate with Forklift, then validate and read the report. Close out and revoke the wave's key.

Sources & targets
vCenter source registry
Shipped
Register each vCenter with its classification level. Plans never span vCenters, so a source is also a plan partition boundary — and CUI-and-above drives the production authorization gate.
OpenShift target catalogs
Shipped
Declare each target cluster plus its networks, storage classes and namespaces, with referential protection on delete. The appliance stores no cluster credentials and never connects.
Resource mappings
Shipped
Translate vSphere port groups and datastores into NADs and StorageClasses, per vCenter-to-cluster pair. Plan generation resolves every VM through a mapping.
AI mapping suggestions
Shipped
The model proposes matches between source resources and your declared catalogs, each with a confidence and a rationale. Suggestions populate the form; nothing is written until you save.
Mapping preflight
Shipped
Read-only readiness check reporting unmapped sources and anything mapped to a target that is not in the cluster's catalog — before a plan fails on it.
vCenter API discovery
Planned
Connect to the vCenter API to enumerate VMs directly, removing the RVTools/CSV step. Today a source is a declarative record; there is no vCenter client.
Inventory
RVTools multi-vCenter import
Shipped
One export can span several vCenters. Each detected hostname is routed to a registered source, and rows that route nowhere are skipped and counted rather than guessed at.
CSV and manual enrollment
Shipped
Parsed in the browser; only the parsed rows reach the appliance. A downloadable template documents every column.
Paginated inventory at fleet scale
Shipped
Server-side paging, sorting, faceted filtering and bulk actions. Page, sort and filters live in the URL, so a filtered view is shareable.
VM lifecycle states
Shipped
Server-enforced available → planned → migrated → rolled back → available, tied to plan lifecycle. Illegal transitions are refused and every change is audited.
Environment auto-detection
Shipped
Derives production/dev/DR from custom attributes, folder, cluster and name, through a signal cascade that returns "unknown" rather than guessing. Feeds the authorization gate.
Per-VM target overrides
Shipped
Bulk set or clear target cluster and namespace on any selection, overriding what the mapping would otherwise resolve.
Baseline collection
SSH state capture
Shipped
Services, listening ports, mounts, cron, kernel and OS, network config — collected with a fixed, read-only command set over Ed25519 keys.
Multi-day scheduling
Shipped
Automatic collection on a configurable cadence across a 3–7 day window, so a nightly job or a weekly restart is not mistaken for migration damage.
Wave-scoped baseline runs
Shipped
Capture the baseline for one plan wave as a tracked run, with per-VM progress, incremental persistence and retry of just the failed hosts.
Windows and Linux collection
Shipped
PowerShell for Windows Server and shell for RHEL, Ubuntu and Debian, with the command set chosen per OS family and shown in the dry run.
Probe coverage
Partial
The first-pass probe catalog is versioned so a baseline records which probes produced it.
Not yet captured: uptime and load, memory, disk usage and time sync are declared in the catalog but disabled, so they are absent from baselines and from the diff.
Agent-based collection
Future
An optional agent for estates where inbound SSH to every VM is not acceptable.
Migration planning
Deterministic wave planner
Shipped
An eight-stage pipeline. Seven stages are pure Python — partitioning, HA anti-affinity splitting, wave packing, concurrency analysis, YAML emission. Structure is never decided by a model.
Per-wave AI rationale
Shipped
The one LLM stage: a description, risk score and notable concerns for each wave. Every wave records whether the text came from the model, a retry, or the deterministic fallback.
HA-aware wave packing
Shipped
At most ten VMs per wave and at most two members of the same HA family, so a cluster never loses quorum to a single wave.
Parallel-safe wave grouping
Shipped
Waves are graph-coloured so two waves sharing a concurrency group can run at the same time — different vCenters and disjoint HA families.
MTV / Forklift YAML
Shipped
Per-wave Plan, NetworkMap and StorageMap, downloadable per wave or as a whole-plan bundle. Generation refuses rather than emitting placeholder names.
Plan dry runs
Shipped
Preview how a selection fans out into partitions, and preview the mechanical grouping, before committing. Neither writes anything or calls the model.
Planning strategies
Partial
Save named planning intents — grouping preference, wave size target, risk appetite, production handling, application atomicity.
Stored, not yet applied: strategies persist and are returned by the API, but no strategy field currently steers plan generation.
Manual wave editing
Planned
Move VMs between waves in the UI when an operator knows something the estate data does not say.
Validation
Six-dimension state diff
Shipped
Services, ports, mounts, cron, kernel/OS and network compared structurally between baseline and post-migration state. Deterministic — no model involved in the comparison.
AI verdict and remediation
Shipped
The model explains what changed and whether it matters, producing a per-VM verdict with findings, evidence and suggested remediation.
Wave-scoped validation runs
Shipped
Validate a whole wave as a tracked run with per-VM verdicts. Refused unless that wave has a completed baseline, because otherwise there is nothing to compare against.
Tiered bulk validation
Shipped
Select by stacking scope axes rather than ticking rows, with a cost preview before running — the most expensive operation in the product.
Scheduled re-validation
Partial
Save a named validation scope and fire it on demand to catch post-cutover drift.
Not yet automatic: saved scopes are not registered with the scheduler, so recurrence does not fire on its own today.
Ansible remediation playbooks
Planned
Turn findings into a reviewable playbook rather than a list of manual steps.
Governance & auditability
Read-only command guard
Shipped
Every command the collector runs passes a fail-closed allowlist at a single choke point, with mutating subcommands denied by name. A future change cannot quietly introduce a write.
Scope: this covers the collector. SSH key revocation writes authorized_keys over SFTP on a separate path that does not pass the guard, the audit or the kill-switch.
SSH command audit
Shipped
Every command is recorded with host, exit status, duration, output size and checksum — including commands the guard refused, which are the interesting ones.
Dry-run wave preview
Shipped
Lists the exact hosts and the exact commands a run would issue, and makes zero connections to produce it. Offered before the run buttons, not after.
Global SSH kill-switch
Shipped
One switch stops all baseline and validation activity immediately; the endpoints refuse while it is off, and the console disables the actions rather than letting you discover it as an error.
Production authorization gate
Shipped
A wave touching production VMs or a CUI-and-above source cannot run without a named authorizer and a written reason, both recorded permanently on the run.
Blast-radius limits
Shipped
Per-vCenter concurrency caps plus a circuit breaker that stops contacting a vCenter after consecutive connection failures instead of hammering it.
Full inference capture
Shipped
Every model call recorded append-only with its input messages, raw output, latency and the method that produced the result — so an LLM answer is distinguishable from a fallback after the fact.
Mutation audit log
Shipped
Every state change with timestamp, actor, resource and structured detail, filterable by action and resource type.
Inference
Runtime backend switching
Shipped
The active backend is a stored setting, changed from the console without a redeploy. Connection details come from the deployment; the picker reports which backends are configured and names the missing variables for those that are not.
Local inference — Ollama
Shipped
The default for a standalone air-gapped appliance. Nothing leaves the box.
In-cluster inference — KServe
Shipped
OpenShift AI InferenceService over the OpenAI-compatible API, authenticating with the pod's service-account token and re-reading it so rotation is handled.
Governed endpoint — Model-as-a-Service
Shipped
An explicit operator opt-in for sites with a governed model endpoint inside their perimeter. The API key comes from a Kubernetes Secret and is never logged, echoed in an error, or returned by the API.
TrustyAI Guardrails
Partial
Proxies a model through the RHOAI Guardrails Orchestrator with input and output detectors. When a detector fires the flow completes on the deterministic fallback — never a server error — and the operator gets a persistent banner plus a labelled entry in the inference log.
Two limits: there is no first-class Helm block yet (configure it through extraEnv), and detection payloads are persisted only on the per-VM validation path, not on plan annotation.
Graceful degradation
Shipped
Every model feature validates its output, retries with corrective feedback, then falls back to deterministic logic. A bad model day produces a less nuanced result, never an error page.
Auth-failure surfacing
Shipped
A rejected key falls back like any other failure but also raises a persistent banner, because otherwise the only symptom is annotation quality quietly getting worse.
Direct vLLM backend
Future
Talk to a vLLM server directly rather than through KServe or a proxy.
Not implemented: the settings are exposed so a later deployment needs no config migration, but the backend raises "not implemented" on every call. It should not be selected.
Design review
Network design review
Shipped
Gap analysis between the source estate's networking and your proposed OCP design — NADs, UDN/CUDN, policies. Coverage gaps, mismatches and missing resources, each with severity, evidence and confidence.
Storage design review
Shipped
The same analysis for storage classes and access modes — including whether live migration is possible with the access modes you have chosen.
Finding triage
Shipped
Accept or dismiss each finding and work the open list down, with the source and proposed evidence attached to every one.
Stated analysis scope
Shipped
A clean review reports what it actually compared, so "no findings" is not mistaken for a clean bill of health when the inputs were thin.
Reporting
Five live reports
Shipped
Executive summary, full validation, failed and degraded, wave plan, and pre-migration baseline snapshot — generated from live data each time they are opened.
Print / PDF export
Shipped
Every report has a print stylesheet that drops the app chrome and flattens to ink on paper, in either theme.
Wave results in reports
Partial
Wave-scoped runs record per-VM verdicts and a structured diff, visible on the wave itself.
Known gap: the report endpoints read the per-VM validation history only, so wave-run results do not yet reach the executive summary or the PDF. A wave failure can under-report there.
CSV findings export
Planned
Machine-readable findings for ingestion into ServiceNow, Jira or a GRC tool.
Security & compliance
Air-gapped operation
Shipped
With the local backend selected, no runtime traffic leaves the network — including the console, which bundles its own fonts and assets. The governed-endpoint backends exist for sites that want them and are opt-in.
Per-wave SSH key catalog
Shipped
Scoped, disposable keys rather than one permanent key with standing access: create for a wave, distribute with the generated Ansible playbook, revoke when validated. Private keys never leave the appliance and are never returned by the API.
FIPS 140-3 mode
Shipped
Detects the host's actual FIPS posture and reports configured, detected and effective separately — so "configured but not active", the classic misconfiguration, is visible rather than assumed.
Hardened container images
Shipped
A minimal, signed, near-zero-CVE image variant alongside the standard UBI 9 build, selected by one Helm value. Both are Red Hat bases, which is what keeps the FIPS supply chain coherent.
SSH host-key policy
Partial
Trust-on-first-use by default, with a strict mode for sites that distribute host keys out of band.
Not yet enforced everywhere: the strict setting is not threaded into the wave-scoped collection path, so it does not take effect there.
Encrypted keys at rest
Planned
Envelope-encrypt stored private keys rather than relying on filesystem permissions alone.
External secret stores
Future
HashiCorp Vault and HSM/TPM-backed key storage for sites that require keys never touch local disk.
CAC / PIV authentication
Future
Smart-card login. Today the authorizer recorded on a run is a caller-supplied assertion, not an authenticated identity.

Technology stack

Built on proven open source

Frontend
React 18 + PatternFly 6
Red Hat's design system, so the console reads like the OpenShift tooling beside it. Fonts and assets are bundled, not fetched.
Backend
Python 3.12 + FastAPI
Typed request and response models, generated OpenAPI, async background work for long-running runs.
Database
PostgreSQL 16
Alembic-versioned schema applied at startup, with no implicit table creation.
Inference
Pluggable, OpenAI-compatible
Ollama, KServe, a governed MaaS endpoint, or TrustyAI Guardrails — chosen at runtime rather than baked into the deployment.
SSH engine
Paramiko + Ed25519
Read-only command set behind a fail-closed guard, with every command recorded.
Scheduler
APScheduler
Drives recurring baseline collection on the configured cadence.
Containers
Podman + UBI 9
Rootless, digest-pinned Red Hat bases, with a hardened variant and Quadlet units for production.
Migration
MTV / Forklift
VirtValidate generates the manifests; Forklift performs the migration. The two stay decoupled deliberately.

Idea capture

How to add new ideas to this map

Capture workflow

  1. Open a GitHub issue with the roadmap label.
  2. Say what problem it solves for an operator, not what it builds.
  3. Add it here as an Idea card in the closest section.
  4. Promote it — idea → planned → partial → shipped — as the code lands.
  5. When it ships, move it into a roadmap milestone.

Keeping this page honest

  • Status means what is in the code, not what is intended.
  • If something half-works, mark it Partial and say what the limit is.
  • Every number in the stats row must be countable from the repo.
  • Re-check this page whenever a feature PR merges — it drifted three months once.

Backlog

  • Drift detection — re-baseline on a cadence and alert on unexplained change
  • Compliance scanning integration (OpenSCAP / STIG) alongside the state diff
  • Migration time estimation from observed wave durations
  • Diff visualization — before/after as a graph rather than a list
  • Snapshot deduplication for long baseline windows at fleet scale
